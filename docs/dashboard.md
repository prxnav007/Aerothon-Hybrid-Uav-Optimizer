# Mission simulation dashboard

Install `requirements.txt`, activate that Python environment, and launch from the repository root:

```bash
python -m streamlit run src/dashboard/app.py
```

The application presents an accelerated replay of a deterministic 15-second time-marching
simulation. `Run simulation` executes the existing `run_mission()` path for the selected frozen
aircraft; playback then advances through stored samples without interpolation or physics changes.

The two selectable aircraft are the exact practical thermostat seed and the exact chromosome read
from `deliverables/optimization/ga_production_seed_20260808/best_found.json`. The latter is labelled
as the best feasible design found by one completed GA seed. GA charts read the completed artifacts
and retain their 60-second optimization-evaluation label; they never launch or resume the GA.

Telemetry downloads are generated in memory from the same dataframe used by the charts. Positive
battery bus power means discharge and negative power means charge. The propulsion architecture is
series hybrid: fuel powers the engine-generator path to the DC bus, the battery connects at that
bus, and the motor alone drives the propeller.

Component efficiency plots use only model-supported quantities. Generator, rectifier, cabling,
inverter and motor efficiencies are the active constant-efficiency parameters; engine thermal,
source-chain, demand-chain and battery terminal efficiencies are calculated at their documented
measurement points. Generator voltage/current, motor torque/RPM/temperature, component maps and a
rolling endurance predictor are omitted because the repository contains no authoritative data for
them.

The committed compact validation result is generated by exactly two missions:

```powershell
python -m src.dashboard.validate_15s
```

This writes `deliverables/validation/mission_15s_validation.json`. Full telemetry remains
uncommitted and is available through the dashboard download buttons.
